# 识别模型补充评估（2026-10-01）

目标：权重允许无需另行申请许可地分发；允许重新录入，比较识别层准确性与 Windows CPU 耗时。生产未切换。

本轮建议优先验证 **SFace + 多角度重新录入**：在独立 LFW、合成降质和 2/5 账户试验中，其通过率和本机速度的综合表现优于 AuraFace。**AuraFace INT8** 留作侧脸对照：本人的小样本中，对单张正脸注册与合成降质更稳，且原生 C++ 可运行，但泛化/低分辨率通过率低于 SFace。没有证据证明两者整体强于现用 R50。SeetaFace6 Light 极快，但当前共享对齐流程中的本人侧脸与 ratio 通过率不足，暂不选；这不等于评价其原生 SDK 的整体精度。

## 许可与公开基准核对

- [AuraFace 模型卡](https://huggingface.co/fal/AuraFace-v1)声明 Apache-2.0，并明确面向商业应用；仅使用其识别头，不把同仓库的其他辅助权重自动当作本次评估或许可对象。作者报告 LFW 99.65%、CFP-FP 95.186%、CPLFW 90.933%。
- [OpenCV SFace 模型目录](https://github.com/opencv/opencv_zoo/tree/main/models/face_recognition_sface#license)明确声明目录所有文件 Apache-2.0。[官方教程](https://docs.opencv.org/4.x/d0/dd4/tutorial_dnn_face.html)报告 LFW 99.60%、CFP-FP 94.80%、CPLFW 91.05%；Zoo README 自己的评估是 99.40%，两种评估不能混为一份结果。SFace 与 AuraFace 在公开姿态测试上互有高低，不能仅凭 R100 或 LFW 的小差异判断优劣。
- [SeetaFace6Open](https://github.com/SeetaFace6Open/index)提供 BSD 许可，并明确免费用于商业和个人用途。官方 Light 的 i7-6700 耗时 9ms，不与本机 ONNX 数字直接横比；公开说明中未找到可同协议比较的 CFP-FP/CPLFW 精度表。社区 ONNX 固定转换来源、原 CSTA 输入及哈希在 `recognizer_research_candidates.json`。本轮验证了固定 Git blob 和 SHA-256；尝试核对官方 Dropbox CSTA 时下载截断，没有完成其原始来源逐字节复核，也未执行原 SDK / 转换数值差分测试。

这些发布方许可允许按条款使用/分发，不需要再申请个别许可；仍须随安装包保留各自许可证和声明。训练数据权利未在本次独立审核。公开配对准确率既不是低 FAR 的认证通过率，也不是 FaceLogin 五帧认证成功率。

## 数据与方法

测试身份 100 个；注册 1 张时有 486 张独立 probe，注册 3 张时有 286 张。两种注册数的 probe 集不相同，不能把差值完全归因于模板数量。各模型在同一注册数下使用完全相同的注册/probe 划分。模型间阈值不同，但标定目标相同；测试集实测 FMR 仍有差异，必须同时看通过率和误接收，不能只排名 TAR。

硬件为 AMD Ryzen 9 7945HX（16 核/32 逻辑处理器），Python ORT 1.19.2。AuraFace INT8 为 S8S8、per-channel Conv/Gemm、MinMax；先将 opset 11 升到 13，并在 8 张标定图上检查 FP32 embedding 最大绝对差 ≤1e-5，再用 64 张标定图生成量化范围。研究模型 SHA-256 为 `502b12c28dbfa8099a12f332927d164f2bbacdaf90cce5a8b807a9dd3f0545be`（见缓存结果/配方记录）；正式 R50 和检测/PAD 模型未改变。

复用前轮 200 个 LFW 身份、1177 张独立源图，以及一个本地身份的成功对齐自拍。标定/测试身份各 100；量化只使用标定身份各一图，共 64 图。注册 1 或最多 3 张图，并且至少保留一张 probe；注册图不会成为 probe。

距离阈值在标定身份上按经验错误账户 FMR ≤0.01% 选择；所有变体保持这个阈值。ratio 0.75/0.85/0.95/1.0 只作敏感性分析，没有用测试结果选择部署参数。

小账户库：每张已知 probe 随机加入 k−1 个异人账户；同一 probe 作为未知人时，从库中排除本人并随机抽 k 个异人账户。每张图重复 30 个库，库中每人有对应数量注册模板；TAR 包含正确识别和距离/ratio 两个门，FPIR 为未知人被任何账户接收。重复库共享人脸图，试验有相关性，不能把重复次数当作独立人数。

32px 与 blur1.5 仅对 probe 的对齐 chip 做合成降质，注册模板保持原图；不代表真实暗光、真实姿态变化或检测能力。my_faces/occlusion_test 未读取，允许遮挡漏检。

## 复现与边界

- 识别权重/量化配方/哈希/个体缓存保存在已忽略的 data/recognizer_ab/，未复制到生产或安装器。
- 旧基准与本次时间不可直接做优化归因；本表是在同一程序内重新测量。线程档仅描述本机，不代表慢机。
- 只有 100 个测试身份，极低误接收率不具备足够统计保证；零观测不等于总体为零。
- 检测先失败时，更换识别器不能恢复该帧；本轮只评估已成功对齐的 chip。
- 未执行摄像头、PAD、连续帧、注册 GUI、锁屏端到端验证。

## 原生 C++ 交叉验证

复用已构建的 `EmbeddingTest.exe`，在 14 张相同自拍 chip 上通过现行 C++ `OnnxRecognizer` 与 ORT DLL 1.23.2 测量：R50 与 AuraFace INT8 均 14/14 成功，512 维。中位 embed 耗时分别为 9.86ms 与 **15.32ms**；同角度距离 p50/p90 分别为 0.692332/0.868638 与 0.638507/0.766769。这是独立的原生小样本测试，不能把两个 ORT 版本的耗时差解释为模型变化。

进程退出码 0、模型加载/推理完成；仍输出了前轮已见的 ONNX schema 重复注册诊断，本轮未修复该运行库问题。SFace 和 SeetaFace 的输入约定不同，没有送入当前 C++ 识别器，原生结果不覆盖它们。
