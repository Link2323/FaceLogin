# SFace 本机解锁与模型耗时（2026-10-03）

当前开发机的常规解锁主要受相机启动、首帧到达和计帧采集间隔限制。SFace 识别推理约 5 ms，未成为当前 3 帧模式的主要延迟来源。本记录保持模型、阈值与计帧策略，末节记录 worker 日志路径修复及服务部署验证。

## 判断与边界

- 本机模型部分最大项为 SCRFD；SFace 三次完整调用约 15 ms，并且部分成本被并行调度覆盖。
- 常规计帧已贴近 60 ms 的采集守卫；继续缩短模型推理不一定同比缩短解锁时间。
- 最大稳定到达延迟是相机就绪后约 278 ms 才有首个有效画面；相机初始化的冷启动波动则是另一长尾来源。
- 预热门结束后的约 33 ms 包含检测结果收集、传感器查询等操作。未单独埋点，不能把该段全部归因于某个驱动 API。

## SFace 初始化根因与修复（23:03–23:15）

一次性 SYSTEM / Session 0 原生探针使用相同生产模型、SHA-256 校验、ORT 1.23.2、线程池创建顺序和推理代码；通过临时计划任务启动无控制台进程，不重定向 stdout/stderr。每种模式 3 次独立进程，轮换运行顺序，完成后删除临时任务。

| 日志路径 | SFace 初始化中位数 | 范围 |
|---|---:|---:|
| 原生产默认 ORT 输出 | 1035.4 ms | 1031.7–1123.8 ms |
| 诊断：仅该 Session 屏蔽 Warning | 27.2 ms | 26.0–27.6 ms |
| 诊断：回调计数，不写日志 | 26.5 ms | 26.5–26.6 ms |
| 诊断：回调完整写入项目日志 | 34.8 ms | 34.3–35.1 ms |

**额外约 1 秒已通过只替换日志路径的对照定位到 ORT 默认输出。** 上游 [默认 sink 选择](https://github.com/microsoft/onnxruntime/blob/v1.23.2/onnxruntime/core/platform/logging/make_platform_default_log_sink.cc) 在 Windows 使用 `CLogSink`；其 [实现](https://github.com/microsoft/onnxruntime/blob/v1.23.2/onnxruntime/core/common/logging/sinks/clog_sink.h) 使用 `std::wclog` 并逐条 flush。探针复现该路径的服务环境成本；尚未进一步分辨 STL、控制台句柄或逐条 flush 各自贡献，不把这段差异归因为模型计算或笼统的整机限流。

最小修复在 `CreateProcessOrtEnv` 指定项目日志回调，Warning 保留为 WARN、Error/Fatal 保留为 ERROR，沿用项目缓冲日志与错误刷盘规则；回调捕获异常，避免异常越过 ORT 的 C 回调边界。未屏蔽 Warning，也未更改模型字节、完整性检查、图优化选项、线程池请求顺序、模型加载顺序、相机激活时机或认证判定。识别、PAD 等各宿主复用这一路径；Service/Console Release 构建及四项测试通过，worker 生命周期覆盖 100 轮。
